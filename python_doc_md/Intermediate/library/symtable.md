# `!symtable`{.interpreted-text role="mod"} \-\-- Access to the compiler\'s symbol tables

::: {.module synopsis="Interface to the compiler's internal symbol tables."}
symtable
:::

**Source code:** `Lib/symtable.py`{.interpreted-text role="source"}

------------------------------------------------------------------------

Symbol tables are generated by the compiler from AST just before bytecode is generated. The symbol table is responsible for calculating the scope of every identifier in the code. `!symtable`{.interpreted-text role="mod"} provides an interface to examine these tables.

## Generating Symbol Tables

:::: function
symtable(code, filename, compile_type, \*, module=None)

Return the toplevel `SymbolTable`{.interpreted-text role="class"} for the Python source *code*. *filename* is the name of the file containing the code. *compile_type* is like the *mode* argument to `compile`{.interpreted-text role="func"}. The optional argument *module* specifies the module name. It is needed to unambiguous `filter <warning-filter>`{.interpreted-text role="ref"} syntax warnings by module name.

::: versionadded
3.15 Added the *module* parameter.
:::
::::

## Examining Symbol Tables

::::::::::: SymbolTableType
An enumeration indicating the type of a `SymbolTable`{.interpreted-text role="class"} object.

::: {.attribute value="\"module\""}
MODULE

Used for the symbol table of a module.
:::

::: {.attribute value="\"function\""}
FUNCTION

Used for the symbol table of a function.
:::

::: {.attribute value="\"class\""}
CLASS

Used for the symbol table of a class.
:::

The following members refer to different flavors of `annotation scopes <annotation-scopes>`{.interpreted-text role="ref"}.

::: {.attribute value="\"annotation\""}
ANNOTATION

Used for annotations if `from __future__ import annotations` is active.
:::

::: {.attribute value="\"type alias\""}
TYPE_ALIAS

Used for the symbol table of `type`{.interpreted-text role="keyword"} constructions.
:::

::: {.attribute value="\"type parameters\""}
TYPE_PARAMETERS

Used for the symbol table of `generic functions <generic-functions>`{.interpreted-text role="ref"} or `generic classes <generic-classes>`{.interpreted-text role="ref"}.
:::

::: {.attribute value="\"type variable\""}
TYPE_VARIABLE

Used for the symbol table of the bound, the constraint tuple or the default value of a single type variable in the formal sense, i.e., a TypeVar, a TypeVarTuple or a ParamSpec object (the latter two do not support a bound or a constraint tuple).
:::

::: method
get_name()

Return the table\'s name. This is the name of the class if the table is for a class, the name of the function if the table is for a function, or `'top'` if the table is global (`get_type`{.interpreted-text role="meth"} returns `'module'`). For type parameter scopes (which are used for generic classes, functions, and type aliases), it is the name of the underlying class, function, or type alias. For type alias scopes, it is the name of the type alias. For `~typing.TypeVar`{.interpreted-text role="class"} bound scopes, it is the name of the `TypeVar`.

:::::::: Class
A namespace of a class. This class inherits from `SymbolTable`{.interpreted-text role="class"}.

::::::: method
get_methods()

Return a tuple containing the names of method-like functions declared in the class.

Here, the term \'method\' designates *any* function defined in the class body via `def`{.interpreted-text role="keyword"} or `async def`{.interpreted-text role="keyword"}.

Functions defined in a deeper scope (e.g., in an inner class) are not picked up by `get_methods`{.interpreted-text role="meth"}.

For example:

::: testsetup
symtable.Class.get_methods

import warnings context = warnings.catch_warnings() context.\_\_enter\_\_() warnings.simplefilter(\"ignore\", category=DeprecationWarning)
:::

::: testcleanup
symtable.Class.get_methods

context.\_\_exit\_\_()
:::

::: doctest
symtable.Class.get_methods

\>\>\> import symtable \>\>\> st = symtable.symtable(\'\'\' \... def outer(): pass \... \... class A: \... def f(): \... def w(): pass \... \... def g(self): pass \... \... \@classmethod \... async def h(cls): pass \... \... global outer \... def outer(self): pass \... \'\'\', \'test\', \'exec\') \>\>\> class_A = st.get_children()\[2\] \>\>\> class_A.get_methods() (\'f\', \'g\', \'h\')
:::

Although `A().f()` raises `TypeError`{.interpreted-text role="exc"} at runtime, `A.f` is still considered as a method-like function.

::: deprecated-removed
3.14 3.16
:::

:::: method
is_free_class()

Return *True* if a class-scoped symbol is free from the perspective of a method.

Consider the following example:

    def f():
        x = 1  # function-scoped
        class C:
            x = 2  # class-scoped
            def method(self):
                return x

In this example, the class-scoped symbol `x` is considered to be free from the perspective of `C.method`, thereby allowing the latter to return *1* at runtime and not *2*.

::: versionadded
3.14

::: method
is_namespace()

Return `True` if name binding introduces new namespace.

If the name is used as the target of a function or class statement, this will be true.

For example:

    >>> table = symtable.symtable("def some_func(): pass", "string", "exec")
    >>> table.lookup("some_func").is_namespace()
    True

Note that a single name can be bound to multiple objects. If the result is `True`, the name may also be bound to other objects, like an int or list, that does not introduce a new namespace.
:::

## Command-Line Usage {#symtable-cli}

::: versionadded
3.13
:::

The `!symtable`{.interpreted-text role="mod"} module can be executed as a script from the command line.

``` sh
python -m symtable [infile...]
```

Symbol tables are generated for the specified Python source files and dumped to stdout. If no input file is specified, the content is read from stdin.
